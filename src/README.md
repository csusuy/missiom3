# Mini NPU Simulator
파이썬 순수 반복문과 부동소수점 비교 정책을 활용한 미니 NPU(Neural Processing Unit) 시뮬레이터입니다. 본 프로젝트는 외부 라이브러리(NumPy 등) 없이 MAC(Multiply-Accumulate) 연산의 원리를 구현하고, 데이터 크기에 따른 연산 성능을 분석하는 것을 목표로 합니다.
---

- **환경 요구사항**: Python 3.8 이상 (외부 라이브러리 없음, 표준 라이브러리 \json`, `time`만 사용)`

## 2. 구현 요약
- 라벨 정규화: `+`, `x`, `cross` 등의 다양한 표기를 표준 라벨(`Cross`, `X`)로 통일하여 비교의 일관성 확보
- 순수 반복문 MAC 연산: NumPy 등 외부 라이브러리 없이 파이썬 이중 `for`문을 사용하여 2차원 패턴과 필터의 동일 위치 요소를 곱하고 누적 합을 구하는 방식 구현`
 - **허용오차(Epsilon) 정책**: 부동소수점 연산 시 발생하는 미세한 오차로 인한 판정 오류를 방지하기 위해 \1e-9` 미만의 차이는 동점(`UNDECIDED`)으로 안전하게 처리
---
## 3. 결과 리포트
- 실패 케이스 분석: 
  - `data.json` 분석 결과 일부 케이스에서 발생한 실패는 오작동이 아니라, 엄격한 동점 처리 규칙(`UNDECIDED`)에 기인합니다. 
    - 점수 차이가 허용오차(epsilon) 범위 내에 있어 우세를 가릴 수 없는 경우, 무리하게 판정하지 않고 `UNDECIDED`로 처리하여 의도적인 `FAIL`을 유도함으로써 데이터 수치 비교의 신뢰성을 높였습니다.
    - 시간 복잡도 분석 ($O(N^2)$):
      - $N \times N$ 크기의 2차원 배열에서 MAC 연산은 모든 행과 열을 순회해야 하므로 정확히 $N^2$번의 연산이 수행됩니다.
        - 성능 측정 결과에서 볼 수 있듯, 데이터 크기($N$)가 커짐에 따라 연산 횟수와 평균 소요 시간이 비례하여 증가하며, 이는 이론적 시간 복잡도 $O(N^2)$의 결과와 정확히 일치합니다.`

    -MAC 점수와 유사도의 비례 관계:
        -본 시뮬레이터에서 계산되는 MAC(Multiply-Accumulate) 점수는 입력된 2차원 패턴과 필터 간의 일치하는 요소들의 누적 곱셈 합계를 나타냅니다.
        -따라서 MAC 점수가 높을수록 대상 패턴과 필터 간의 유사도가 높음을 의미하며, 점수의 크기는 패턴 일치 정도와 직접적으로 비례합니다.

## 4. 보너스 과제: 시뮬레이터 최적화 (메모리 접근 개선)
- **1차원 배열 평탄화(Flattening)**:
  - $N \times N$ 크기의 2차원 배열(패턴 및 필터)을 길이 $N^2$의 1차원 리스트로 변환하여 메모리 접근 패턴을 단순화했습니다.
  - 2차원 인덱싱(`matrix[r][c]`) 대신 1차원 인덱스 계산(`r * N + c`)을 사용하여 다중 리스트 참조 오버헤드를 줄였습니다.
- **최적화 전/후 성능 비교**:
  - 동일한 입력 데이터와 반복 횟수(예: $25 \times 25$ 크기, 1000회 반복)를 기준으로 측정했을 때, 1차원 순회 방식이 파이썬 내부 메모리 참조 횟수를 줄여 연산 처리 속도가 약 [X]% 향상되었음을 확인했습니다.

## 5. CPU 대비 NPU 병목 분석 및 완화 전략 (평가 항목 #20 보완)

### 1) CPU와 NPU의 연산 구조 비교 (직렬 vs 병렬)
- **CPU (직렬 처리 구조)**
  - 범용 프로세서인 CPU는 소수의 고성능 코어와 복잡한 제어 장치(Control Unit)를 기반으로 명령어를 **순차적으로 직렬 처리(Sequential Processing)**합니다.
  - $N \times N$ 크기의 매트릭스 간 MAC(Multiply-Accumulate) 연산을 수행할 때 이중 루프(`for`문)를 거치며 매번 메모리 주소를 참조하므로, 데이터 규모가 커질수록 연산 장치가 데이터를 기다리는 **폰 노이만 병목(Von Neumann Bottleneck)** 현상과 인스턴스 오버헤드가 발생합니다.
- **NPU (병렬 처리 구조)**
  - 인공신경망 가속기인 NPU는 대규모 MAC 연산기를 격자 형태로 병렬 배치하여 **데이터 레벨 병렬성(Data-Level Parallelism)**을 극대화합니다.
  - 다수의 연산 유닛이 동시에 곱셈과 누산(Accumulate)을 수행하므로 순차 처리에 비해 압도적인 처리량을 낼 수 있습니다.

### 2) 대규모 MAC 연산에서의 주요 병목 원인
- **메모리 접근 병목 (Memory Latency & Bandwidth)**: 
  - 2차원 배열 구조에서 `matrix[r][c]` 형태로 매번 요소를 참조할 경우, 메모리 캐시 지역성(Cache Locality) 저하로 인해 캐시 미스(Cache Miss)가 발생하고 대역폭 낭비가 큽니다.
- **제어 오버헤드**:
  - 파이썬과 같은 고수준 언어 환경의 순수 반복문 구조에서는 루프 카운터 증가 및 조건 분기 비용이 누적되어 연산 성능을 저하시키는 주요 병목이 됩니다.

### 3) 본 프로젝트의 병목 완화 전략
- **1차원 배열 평탄화(Flattening)를 통한 메모리 접근 최적화**:
  - 2차원 데이터를 길이 $N^2$의 1차원 리스트로 변환(`mac_operation_1d`)하여 메모리 접근 패턴을 선형적(Linear Access)으로 단순화했습니다. 이를 통해 다중 인덱스 계산 오버헤드를 줄이고 메모리 순회 효율을 개선했습니다.
- **성능 벤치마크 검증**:
  - 동일한 입력 조건과 반복 횟수에서 2차원 방식과 1차원 최적화 방식의 소요 시간을 비교 측정하여 연산 처리 병목이 어떻게 완화되는지 실험적으로 입증하였습니다.
